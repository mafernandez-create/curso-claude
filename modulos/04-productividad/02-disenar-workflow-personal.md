# Diseñar un workflow personal: plantilla de trabajo

## Objetivos de aprendizaje

Al terminar esta lección serás capaz de:

- [ ] Explicar qué es un **workflow** con Claude y por qué conviene formalizarlo.
- [ ] Aplicar una **plantilla de cuatro partes** (objetivo, prompt base, proceso, criterio de éxito).
- [ ] Diseñar tu primer workflow reutilizable para una tarea que repites.

## Prerrequisitos

- Lección 01 del módulo.

## Contexto

Un truco aislado se olvida; un **workflow** se reutiliza. Si una tarea la haces a menudo (redactar actas, analizar un Excel, revisar contratos), merece la pena convertir tu forma de pedírsela a Claude en un proceso documentado que puedas repetir y mejorar.

## Contenido principal

### 1. Qué es un workflow

Es una **secuencia repetible** de pasos para resolver un tipo de tarea con Claude: qué contexto le das, qué le pides, cómo iteras y cómo validas. No es magia: es convertir tu mejor manera de hacerlo en algo que no tengas que reinventar cada vez.

### 2. La plantilla de cuatro partes

1. **Objetivo:** qué resultado quieres y para quién.
2. **Prompt base:** el mensaje de partida (con huecos para rellenar).
3. **Proceso paso a paso:** la secuencia (pedir borrador → revisar → afinar → validar).
4. **Criterio de éxito:** cómo sabes que está bien.

### 3. Mejóralo con el uso

Un workflow no nace perfecto. Cada vez que lo usas, anota qué falló y ajusta el prompt base o los pasos. En pocas iteraciones tendrás un proceso fiable.

## Ejemplo aplicado

Workflow "Acta de reunión":
- **Objetivo:** acta clara a partir de mis notas, para enviar al equipo.
- **Prompt base:** `A partir de estas notas [pegar], redacta un acta con: asistentes, decisiones, tareas (responsable y fecha). Tono neutro.`
- **Proceso:** pegar notas → revisar que no falten tareas → pedir ajustes → validar.
- **Criterio de éxito:** toda decisión tiene su tarea con responsable.

## Ejercicio práctico

1. Elige una tarea que repitas al menos semanalmente.
2. Documenta su workflow con la plantilla de cuatro partes.
3. Úsalo dos veces y anota una mejora.
4. **Criterio de éxito:** tienes un workflow escrito que puedes reutilizar sin pensar desde cero.

## Errores comunes

- **No documentarlo:** si vive solo en tu cabeza, lo reinventas cada vez.
- **Sobrediseñar:** empieza simple; añade pasos solo cuando un fallo lo justifique.

## Resumen en 3 frases

1. Un workflow convierte tu mejor forma de pedir una tarea en un proceso repetible.
2. La plantilla tiene cuatro partes: objetivo, prompt base, proceso y criterio de éxito.
3. Se perfecciona con el uso: documenta, prueba y ajusta.
